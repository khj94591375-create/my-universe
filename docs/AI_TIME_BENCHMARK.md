- 측정일: 2026-11-25
- 모델: `claude-haiku-5-5` (빠른 모델, 3번 모두 이 모델로 응답, 다시 시도 없음)
- 원고: `public/samples/star-library-1-6.txt`에서 "N화 제목" 줄을 뺀 문단을 두 번 이어 붙인 뒤, 문단 경계에서 잘라 **4,996자**로 만듦. 첫 줄은 "1화 등불이 켜진 밤".
- 방법: `supabase/functions/_shared/claude.ts`의 `askJson`과 같은 프롬프트·스키마·설정으로 Claude를 직접 호출.
  순서: 회차·장면 나누기(split-episodes) 1번 → 회차 정리(analyze-episode) 1번 → 맞춤법(spell-check) 2번.
  맞춤법은 `src/features/spell/text.ts`의 `splitForCheck`로 나눔(2,990자 + 1,993자). 이 순서를 3번 반복.

## 2. 단계별 기다리는 시간

브라우저 처리 시간은 이미 잰 값(글자 뽑기 0.05초, 저장 화면 0.15초, 규칙 맞춤법 0.15초)을 썼다.

| 단계 | 기다리는 시간 (평균, 최대) |
|---|---|
| ① 원고 올리기: 글자 뽑기 + AI 회차 나누기 | 약 4.5초 (최대 5.4초) |
| ② 저장 화면 | 0.15초 + 서버 요청 17번 (재지 않음) |
| ③ AI 회차 정리 | 약 12.8초 (최대 17.5초) |

## 4. 쉽게 말하면

- 기다리는 시간은 거의 다 AI다. 그중 **맞춤법 검사(약 16초)**와 **회차 정리(약 13초)**가 가장 길다.
- 맞춤법은 앱에서도 두 묶음을 하나씩 차례로 보낸다(`src/screens/episodes/sections/SpellCheckSection.tsx`). 그래서 두 시간을 더했다.
- 회차 정리는 회마다 10초에서 17.5초까지 차이가 컸다. AI가 쓰는 답의 길이(출력 2,665~4,047토큰)가 매번 달라서다.

## 5. 빠진 부분

- Claude를 직접 불러서 쟀다. 실제 앱의 서버 함수가 켜지는 시간과 로그인·데이터 확인 시간은 빠져 있다. 실제로는 요청마다 1초 안팎 더 걸릴 수 있다.
- 저장할 때 보내는 서버 요청 17번의 시간은 재지 않았다.
- 회차 정리에 넣은 장면은 AI가 나눈 장면 9개를 그대로 썼다(설정집·이전 회차 없음, 새 작품의 1화와 같은 상태).
- 맞춤법의 보호 단어는 "없음"으로 보냈다.
